# OCRWeb 微信内置浏览器兼容性检查清单

> Last updated: 2026-06-10
> Scope: 仅适用于微信聊天中点开链接后进入的微信内置 WebView。
> In scope: `iPhone 微信内置浏览器`、`Android 微信内置浏览器`
> Out of scope by default: 桌面浏览器、独立 Safari、独立 Chrome、其他 App 内 WebView

## 使用方式

本清单只负责微信内置浏览器兼容性检查与问题记录，不负责桌面 QA，也不替代通用的 `docs/post-dev-qa-checklist.md`。

执行顺序固定为：

1. 先填写测试矩阵
2. 再按页面 smoke flow 实测
3. 最后按问题模板记录不通过项

不要在未写清设备、系统版本、微信版本前就下兼容性结论。

## 风险分级

- `P0`: 页面打不开、主入口不可点、严重遮挡、横向炸开、卡死
- `P1`: 吸顶错位、锚点不准、复制/下载失效、弹层异常
- `P2`: 视觉轻微偏差、过渡抖动、体验退化但可完成任务

## 当前代码对应的微信高风险机制

### 1. `clipboard` 复制

覆盖点：

- 详情页 `EndpointRow` 的地址复制
- 详情页 `CopyTextButton` 的代码示例复制

检查点：

- 点击复制后是否真正进入系统剪贴板
- 失败时是否静默失效
- 按钮文案是否错误显示为“已复制”

### 2. `download` 下载

覆盖点：

- 开通流程页“下载申请表”
- 详情页“下载本接口 PDF”

检查点：

- 微信内置浏览器是否允许直接下载
- 是否跳转到预览页而非下载
- 是否点击后无响应

### 3. `sticky` 与安全区

覆盖点：

- 顶部站点导航
- 详情页吸顶导航
- 开通流程页相关吸顶区

检查点：

- 是否被微信顶部栏遮住
- 是否在滚动中抖动
- 是否脱离文档流或遮挡正文

### 4. 锚点跳转与滚动恢复

覆盖点：

- 详情页左侧导航 / 移动端锚点
- 路由切换后的 `sessionStorage` 恢复滚动

检查点：

- 进入详情页后是否跳错位置
- 返回后是否落在错误滚动点
- 锚点目标是否被吸顶头部挡住

### 5. 观察器依赖

覆盖点：

- `IntersectionObserver`
- `ResizeObserver`

检查点：

- 详情页当前激活导航是否正常更新
- 移动端吸顶导航是否出现/消失异常
- 头部高度变量是否计算错误

### 6. 视口高度与弹层

覆盖点：

- `100vh`
- lightbox `max-height: calc(100vh - 20px)`
- `safe-area-inset-top`

检查点：

- 微信地址栏伸缩时页面是否跳动
- 图片预览弹层是否超屏
- 关闭弹层后是否回滚异常

### 7. 横向溢出与横向滚动

覆盖点：

- 首页分类目录链接区 `.home-directory-links`
- 窄屏顶部导航
- 详情页代码块 / 参数区

检查点：

- 当前移动端首页主入口是否能正常点击
- 目录双列是否挤出视口
- 顶部导航是否触发整页误滑
- 是否触发整页误滑
- 是否出现整页横向溢出

## 页面 smoke flow

### 首页 `/`

1. 打开页面
2. 确认手机端首屏为顶部导航 + “接口图鉴”分类目录，不按桌面端搜索框、分类 chips 或档案卡片作为主入口验收
3. 检查首屏和目录区域无整页横向滚动
4. 点击目录中的“二代证（人像页+国徽页）”，或任一可见 `.home-directory-link`
5. 确认进入详情页后能看到标题、测试地址、生产地址、请求参数和返回参数入口
6. 返回首页，检查滚动位置和目录布局是否异常

### 开通流程页 `/activation-guide`

1. 打开页面
2. 检查顶部导航与页面主流程是否正常
3. 打开一张截图大图，再关闭
4. 点击“下载申请表”
5. 检查页面滚动、弹层锁滚、按钮点击反馈

### 详情页 `/interfaces/idcard`

1. 打开页面
2. 点击请求参数、返回参数、任一二级锚点
3. 点击复制测试/生产地址
4. 复制一段代码示例
5. 返回首页再重新进入

### 详情页 `/interfaces/vat-invoice`

1. 打开页面
2. 重复 `idcard` 页面相同流程
3. 确认不是单页偶发问题

## 本地模拟预检记录

### 2026-06-10 本地 Chromium + 微信 UA 预检

说明：

- 该结果只用于真机微信前的前置筛查，不代表 `iPhone 微信内置浏览器` 或 `Android 微信内置浏览器` 已通过
- 模拟环境为本地 Chromium、微信 User-Agent、移动视口
- 模拟视口：iPhone `390x844`，Android `393x873`

已筛查页面：

- `/`
- `/activation-guide`
- `/interfaces/idcard`
- `/interfaces/vat-invoice`

预检通过点：

- 四个目标页面均可打开
- iPhone 与 Android 模拟视口下未发现整页横向溢出，`scrollWidth === clientWidth`
- 开通流程页截图 lightbox 可打开和关闭
- 开通流程页“下载申请表”链接可被点击；真实微信下载行为仍需真机确认
- 详情页测试/生产地址区存在，复制按钮和主要锚点入口可点击；真实剪贴板写入仍需真机确认

预检发现：

- 当前手机端首页真实结构是“接口图鉴分类目录”优先；`.home-hero`、搜索框、分类 chips、档案卡片网格不是移动端主流程验收入口
- 首页 smoke flow 已改为点击 `.home-directory-link` 进入详情页
- 补充预检中，iPhone 与 Android 模拟视口均显示 44 个可见目录链接，点击 `data-slug="idcard"` 可进入 `/interfaces/idcard`，返回后回到 `/` 且未出现横向溢出
- `/interfaces/idcard` 出现 React duplicate key warning，关键词为 `Nation` / `card-Nation`；这不是微信专属问题，但可能影响后续代码清理或详情页稳定性排查

待真机确认：

- 微信内置浏览器是否允许 `navigator.clipboard.writeText`
- 微信内置浏览器点击 `download` 链接后的真实行为
- `sticky` 区域是否被微信顶部栏或安全区影响
- 锚点跳转和返回首页后的滚动恢复是否稳定
- lightbox 在真实微信地址栏伸缩时是否超屏或回滚异常
- 详情页代码块、参数区和顶部导航是否触发整页横向溢出
